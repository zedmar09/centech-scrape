# Laravel Flexepos Fallback API

Server-to-server API reference for retrieving Sales and Royalties data from
Flexepos when an official POS data file is missing.

## Overview

| Item | Value |
|---|---|
| Base URL | The deployed `centech-scrape` URL |
| Authentication | Bearer token |
| Request format | `application/json` |
| Success format | `application/x-ndjson` |
| Sales batch limit | 3 jobs |
| Royalties batch limit | 6 jobs |
| Recommended request concurrency | 2 requests |

The normal POS import remains the primary source. Laravel should mark data from
this API as fallback data. If the official POS file arrives later, the official
data should replace or supersede the scraped data.

### How a request works

1. Laravel identifies missing store/date data.
2. Laravel sends a batch of jobs to one of the endpoints.
3. One request opens one Browserless connection.
4. The scraper logs into Flexepos and processes the jobs.
5. The HTTP response streams one NDJSON event per line.
6. Laravel matches each event to its job using `job_id`.
7. Laravel saves completed rows and retries failed or incomplete jobs.

## Authentication

Configure the same secret in Vercel and Laravel:

```env
FLEXEPOS_SCRAPER_API_TOKEN=<long-random-secret>
```

Required headers:

```http
Authorization: Bearer <FLEXEPOS_SCRAPER_API_TOKEN>
Content-Type: application/json
Accept: application/x-ndjson
```

The token is for server-to-server use only. Do not expose it to a browser,
client component, or public JavaScript bundle.

## Common request fields

| Field | Type | Required | Rules | Description |
|---|---|---:|---|---|
| `request_id` | string | Yes | 1–100 URL-safe characters | Unique ID for this HTTP batch. Use a new value for a retry batch. |
| `jobs` | array | Yes | At least one job | Jobs to scrape in this request. |
| `jobs[].job_id` | string | Yes | 1–100 URL-safe characters; unique in the batch | Durable job ID generated by Laravel. Keep it unchanged when retrying. |
| `jobs[].organization` | string | Yes | `century` or `century_austin` | Organization containing the store. |
| `jobs[].store_number` | string | Yes | Must be configured for the organization | Flexepos store number. Century store `4083` is excluded. |
| `jobs[].attempt` | integer | Yes | 1–10 | Current attempt. Normal automatic retry uses attempt `2`. |

Dates use the ISO format `YYYY-MM-DD` and must be real calendar dates.

## POST `/api/internal/flexepos/sales`

Scrapes Sales data. Each job represents one store on one business date.

### Execution behavior

One Sales request accepts up to three jobs and opens one Browserless
connection. The connection creates three isolated Flexepos sessions, so all
three jobs can run concurrently.

Laravel may run up to two requests concurrently:

```text
2 Browserless connections × 3 isolated sessions = 6 active Sales jobs
```

### Sales-specific fields

| Field | Type | Required | Rules | Description |
|---|---|---:|---|---|
| `jobs[].business_date` | string | Yes | Valid `YYYY-MM-DD` date | Business date to scrape. |

The combination of organization, store number, and business date must be unique
within the request.

### Example request

```json
{
  "request_id": "sales-batch-20260701-001",
  "jobs": [
    {
      "job_id": "sales-20260701-2006",
      "organization": "century",
      "business_date": "2026-07-01",
      "store_number": "2006",
      "attempt": 1
    },
    {
      "job_id": "sales-20260701-2016",
      "organization": "century",
      "business_date": "2026-07-01",
      "store_number": "2016",
      "attempt": 1
    }
  ]
}
```

### Completed Sales row

| Field | Type | Nullable | Description |
|---|---|---:|---|
| `business_date` | string | No | Scraped business date. |
| `store_number` | string | No | Scraped store. |
| `category_code` | string | No | Stable, database-friendly category identifier. |
| `category_name` | string | No | Human-readable transaction category. |
| `debit` | decimal string | Yes | Two-decimal debit amount, such as `"197.53"`. |
| `credit` | decimal string | Yes | Two-decimal credit amount, such as `"197.53"`. |

## POST `/api/internal/flexepos/royalties`

Scrapes Royalties data. Each job represents one store for one date range.

### Execution behavior

A Royalties request accepts up to six jobs. Royalties currently uses one
isolated Flexepos session per Browserless connection and processes jobs
sequentially within the request.

### Royalties-specific fields

| Field | Type | Required | Rules | Description |
|---|---|---:|---|---|
| `jobs[].start_date` | string | Yes | Valid `YYYY-MM-DD` date | First date in the royalty period. |
| `jobs[].end_date` | string | Yes | Valid `YYYY-MM-DD`; not before `start_date` | Last date in the royalty period. |

The combination of organization, store number, start date, and end date must be
unique within the request.

### Example request

```json
{
  "request_id": "royalties-20260701-20260720-001",
  "jobs": [
    {
      "job_id": "royalties-20260701-20260720-2006",
      "organization": "century",
      "start_date": "2026-07-01",
      "end_date": "2026-07-20",
      "store_number": "2006",
      "attempt": 1
    }
  ]
}
```

### Completed Royalties row

| Field | Type | Nullable | Description |
|---|---|---:|---|
| `start_date` | string | No | First date in the royalty period. |
| `end_date` | string | No | Last date in the royalty period. |
| `store_number` | string | No | Scraped store. |
| `category_code` | string | No | Stable, database-friendly category identifier. |
| `category_name` | string | No | Human-readable transaction category. |
| `debit` | decimal string | Yes | Two-decimal debit amount. |
| `credit` | decimal string | Yes | Two-decimal credit amount. |

## Successful response: NDJSON

The success response uses:

```http
Content-Type: application/x-ndjson; charset=utf-8
```

NDJSON means newline-delimited JSON. Each line is an independent JSON object:

```json
{"type":"job_started","request_id":"sales-batch-20260701-001","job_id":"sales-20260701-2006","organization":"century","store_number":"2006","business_date":"2026-07-01","attempt":1}
{"type":"job_completed","request_id":"sales-batch-20260701-001","job_id":"sales-20260701-2006","organization":"century","store_number":"2006","business_date":"2026-07-01","attempt":1,"rows":[{"business_date":"2026-07-01","store_number":"2006","category_code":"subject_to_tax","category_name":"Subject to Tax","debit":null,"credit":"197.53"}]}
{"type":"session_completed","request_id":"sales-batch-20260701-001","elapsed_ms":22639}
```

The response is not a JSON array. Laravel should not call `$response->json()`.
It should read the body as a stream, buffer partial text, and process complete
lines separated by `\n`.

An HTTP chunk may contain part of one line or several lines. Chunk boundaries
must not be treated as event boundaries.

## Event reference

| Event type | Job terminal? | Important fields | Meaning |
|---|---:|---|---|
| `job_started` | No | Job metadata, `context_index` when available | The job started in Flexepos. |
| `job_completed` | Yes | Job metadata, `rows` | The job succeeded. Save its rows. |
| `job_failed` | Yes | Job metadata, `error` | The individual job failed. Retry it if attempts remain. |
| `context_failed` | No | `context_index`, `error` | An isolated Flexepos context failed. Check which requested jobs have no terminal event. |
| `session_failed` | No | `request_id`, `error` | The Browserless request failed. Jobs without terminal events are incomplete. |
| `session_completed` | No | `request_id`, `elapsed_ms` | The scraper request ended. This does not guarantee every job completed. |

Common job event fields:

| Field | Type | Description |
|---|---|---|
| `type` | string | Event type. |
| `request_id` | string | Laravel batch ID from the request. |
| `job_id` | string | Laravel job ID from the request. |
| `organization` | string | Job organization. |
| `store_number` | string | Job store. |
| `attempt` | integer | Attempt sent by Laravel. |
| `context_index` | integer | Isolated session number, when available. |
| `error` | string | Failure message, when applicable. |
| `elapsed_ms` | integer | Session duration, when applicable. |

## HTTP errors

Errors produced before scraping are returned as ordinary JSON, not NDJSON.

| Status | Meaning | Example cause |
|---:|---|---|
| `400` | Bad Request | Malformed JSON. |
| `401` | Unauthorized | Missing or incorrect bearer token. |
| `413` | Content Too Large | Request body exceeds 64 KB. |
| `415` | Unsupported Media Type | Missing `Content-Type: application/json`. |
| `422` | Unprocessable Content | Invalid dates, unsupported store, duplicate job, or too many jobs. |
| `503` | Service Unavailable | `FLEXEPOS_SCRAPER_API_TOKEN` is not configured. |

Example:

```json
{
  "error": "jobs must not contain more than 3 jobs."
}
```

An accepted scrape normally returns HTTP `200` even when an individual job
fails. Job-level failures are represented by `job_failed` NDJSON events.

## Retry behavior

Laravel owns retries; the endpoint does not automatically resend failed jobs.

For each request, Laravel should record the requested `job_id` values and then
classify them:

| Result | Laravel action |
|---|---|
| Received `job_completed` | Save the rows and mark the job completed. |
| Received `job_failed` on attempt 1 | Requeue the job with `attempt: 2`. |
| Received no terminal event | Treat it as incomplete and requeue with `attempt: 2`. |
| Failed or incomplete on attempt 2 | Mark failed for manual review or manual retry. |

Use the same `job_id` when retrying because it represents the same logical job.
Use a new `request_id` because the retry is a new HTTP request.

Example retry:

```json
{
  "request_id": "sales-retry-20260701-002",
  "jobs": [
    {
      "job_id": "sales-20260701-2006",
      "organization": "century",
      "business_date": "2026-07-01",
      "store_number": "2006",
      "attempt": 2
    }
  ]
}
```

## Manual testing

Import
[`CENTECH_SCRAPER_API.postman_collection.json`](./CENTECH_SCRAPER_API.postman_collection.json)
into Postman.

Set these collection variables:

| Variable | Example |
|---|---|
| `base_url` | `http://localhost:3000` |
| `api_token` | The local `FLEXEPOS_SCRAPER_API_TOKEN` value |

Postman may display the NDJSON response only after the request finishes. To
observe events as they arrive, use `curl --no-buffer`.
